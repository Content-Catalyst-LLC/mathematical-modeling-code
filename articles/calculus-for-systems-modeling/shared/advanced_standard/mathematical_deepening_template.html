Mathematical Deepening

This section adds a more formal layer for mathematically advanced readers. It does not replace the article’s conceptual explanation; it clarifies the definitions, assumptions, counterexamples, and computational conditions under which the model can be interpreted.

Formal Definitions

Definition

A function should be treated as a structured object with a domain, codomain, and graph satisfying the condition that each admissible input is assigned exactly one output.

Codomain and Image

The image or range of a function is the set of outputs actually attained. It may be a proper subset of the codomain. Confusing codomain with image can overstate what a model can produce.

Feasible Set

A feasible set is the subset of admissible inputs, states, or decisions satisfying the model’s constraints. Optimization and policy interpretation should usually occur over this set, not over an unconstrained ambient space.

Invariant Set

An invariant set is a region of state space that trajectories remain inside under the model dynamics. For population, stock, resource, and risk models, invariance often encodes nonnegativity and capacity constraints.

Propositions and Counterexamples

Proposition

If a model is differentiated, integrated, optimized, or simulated, the relevant operation should be valid on the domain or feasible region where the model is being interpreted.

Counterexample

A formula can be computable outside its modeling domain. The resulting number may be mathematically generated but uninterpretable as a systems-modeling output.

Boundary Case

Many modeling failures occur near zero, capacity limits, thresholds, discontinuities, singularities, or domain boundaries. These cases should be tested explicitly.

Numerical Warning

Smaller numerical steps do not automatically mean better interpretation. Roundoff, instability, stiffness, discontinuity, and model misspecification can dominate formal truncation-error improvements.
